# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

@AGENTS.md

## What this is

BytNode-AI: a local Next.js 16 (App Router, Turbopack) + React 19 + TypeScript-strict app. Multi-agent finance chat on OpenRouter; each agent has a *profession* (prompt + skills loaded from `professions/`), a tool set (`lib/tools/`), and BytNode market data via a remote MCP server. UI text, comments and commit-style prose are in French; keep it that way. CSS is hand-written (no Tailwind) using the BytNode tokens (`--ink`, `--paper`, `--voile`) and fonts (Geist / Inter / IBM Plex Mono) — see `README.md` for the full layout.

## Where this sits

This folder is the git root (`benjfrem07/bytnode-ai`). The sibling `../app-web/` is a separate
repository, not part of this one. The app is **published on npm as `bytnode-ai`**: `npx bytnode-ai` is the *install* step —
`bin/bytnode-ai.mjs`, seeing `_npx` in its own path, runs `npm install -g bytnode-ai@<same version>`
so the plain `bytnode-ai` command exists afterwards (`npx bytnode-ai@latest` = update; a failed
global install is reported and the app starts anyway). Packaging: `package.json` `files` is a whitelist (`bin`, `.next`, `lib` minus tests,
`professions`, `types`, the three config files), `prepack` (`scripts/prepack.ts`) does a clean
`next build`, drops `.next/cache`, rewrites the hashed aliases Turbopack uses for
`serverExternalPackages` (symlinks in `.next/node_modules` → the build machine's absolute
`node_modules`; shipped as-is they fail with "Cannot find module 'fast-glob-461a…'"), and refuses
the archive if `lib/publish/pack-check.ts` finds `.env*`, `workspaces/`, `sandboxes/`, `.mcp.json`
or a `cb_live_`/`sk-or-v1-` key, or this machine's absolute path (`.next/required-server-files.json`
carries `appDir`; prepack blanks it — `next start` never reads it). `bin/bytnode-ai.mjs` runs `next start` **with `cwd` = the package
dir**, which is why `PROJECT_ROOT = process.cwd()` still holds everywhere. User data never lives
in the project: `lib/server/data-dir.ts` (`~/.bytnode-ai/`, `BYTNODE_AI_HOME`) holds workspaces,
installed agents and personal skills. `.github/workflows/pack.yml` runs typecheck, tests and
`smoke:pack` on ubuntu/macos/windows — locally only Windows is ever exercised.

Before reporting a change as done: `typecheck`, `lint`, `test` must all be clean.

Commit subjects follow the history: French, `<domaine> : <résumé>` (`exchange : …`, `securite : …`, `doc : …`), written without accents. Design specs and implementation plans live in `docs/superpowers/specs/` and `docs/superpowers/plans/` (`YYYY-MM-DD-<sujet>.md`); read the matching spec before touching a feature that has one.

Environment (server-side, optional): `OPENROUTER_BASE_URL` (relay / fake OpenRouter), `OPENROUTER_SEARCH_MODEL`, `BYTNODE_MCP_URL`. The OpenRouter key is **not** read from env by the app — it lives in the browser's `localStorage` and travels per request in the `x-openrouter-key` header (`lib/server/openrouter.ts`); the BytNode key uses `x-bytnode-key`. `.env.local` holds a real key used only by ad-hoc test scripts: never print it. Real-model probes of the ACP path cost the user's subscription quota — keep them short (`haiku`, `effort: low`). `.probe-acp.mjs` (tracked, root) is a token-free ACP handshake probe: `node .probe-acp.mjs copilot|grok|gemini` spawns the agent from `~/.bytnode-ai/agents/<id>/` with API-key env vars stripped and prints `initialize`/`session/new` — the first thing to run when an agent shows « ne répond pas ».

## Constraints that are not obvious from the code

- Next 16 refuses two `next dev` in the same directory, and port 3777 is the user's. Don't leave background servers running; kill anything you started.
- Bash tool heredocs mangle backslashes on this machine — write files with the Write tool (or a python patch script in the scratchpad) rather than `cat <<EOF`.
- ESLint runs the React Compiler rules: no `Date.now()`/random ids in render (stamp ids at creation), no `setState` inside effects (key the component instead), stable `useCallback` deps.
- Packages with native binaries or runtime `require` (`@vscode/ripgrep`, `pdf-parse`, `turndown`, `@joplin/turndown-plugin-gfm`, `fast-glob`, `@agentclientprotocol/sdk`, `@resvg/resvg-js`, `ccxt`) must stay in `serverExternalPackages` in `next.config.ts`. `pdf-parse` v2 is class-based (`new PDFParse({data}).getText()`).
- `bytnode_api/.mcp.json` (if present) contains a live key — never reuse it.

## Architecture (what you need across several files)

**Isomorphic agent loop.** `lib/agent/loop.ts` (`runAgentLoop(messages, deps)`) is the model → tools → model cycle, max 40 turns. It is dependency-injected and runs in two places:
- *Browser*, for the main agent (`components/chat/use-chat.ts`): model via `POST /api/chat` (SSE relay, `lib/llm/client.ts` + `sse.ts`), tools via `POST /api/tools/execute` (NDJSON stream of lines / sub-agent events / result), permissions resolved by UI promises (`answer(callId, allow, always)`).
- *Server*, for Workflow sub-agents (`lib/tools/agents/workflow.ts`), everything in-process.

**Sub-agents (`Workflow`).** Both engines have the tool; **a sub-agent is always one of the four professions** — `tasks[].profession` is a required enum, the agent picks the profession by the nature of the task and `tasks[].model` by its difficulty (any OpenRouter id for key agents; for ACP agents the enum lists the agent's own models, fetched from `/api/acp/models` at the first `tools/list`). Shared pure module `lib/tools/agents/subagent.ts` (tested): `workflowDescription`/`workflowParameters`, `readTasks`, `runInPool` (3 at a time, 8 max), `subagentFrame` (profession `PROMPT.md` + "one task, one report, no delegation, no funds"), `reportSection` (`## <titre> — <Profession>`) and `parseWorkflowReport`, which the thread uses to split the output when nothing was streamed. A sub-agent gets the profession's skills, `buildToolsPrompt(..., subagent=true)` / `buildAcpPrompt(..., subagent=true)` (no Workflow, exchange section read-only via `exchangePromptSection(..., readOnly)`), every tool but Workflow and the five action exchange tools (`allowedForSubagent`), and asks no permission. *Key agents*: `workflow.ts` runs `runAgentLoop` server-side per task and emits `subagent` events carrying `profession` and the final `report`; `use-chat.ts` stores them as `Step.tool.subagents` (report capped at `STORED_REPORT`). *ACP agents*: `lib/mcp/finance-server.ts` serves `Workflow` only at `BYTNODE_AI_DEPTH=0` (a sub-agent's server, depth 1, also drops the action exchange tools) and validates MCP arguments with `validateArgs` (which now recurses into array items / nested objects: `tasks[1].profession`); `lib/mcp/acp-workflow.ts` posts each task to `POST /api/acp/subagent` (NDJSON: `tick` every 15 s, then `done`/`error`) with the per-conversation token that `sessions.ts` put in the server's env (`BYTNODE_AI_PARENT`, `BYTNODE_AI_ACP_AGENT`, `BYTNODE_AI_ORIGIN` = request origin, `BYTNODE_AI_SUBAGENT_TOKEN`, stable per conversation so the session key doesn't churn); `runSubagent` requires the parent to be live **and busy**, opens a throwaway session of the same agent in the same workspace (profession prompt in `sessionMeta`, model/effort via `applyConfig`, MCP servers at depth 1), auto-allows permissions except `isAlwaysAskTitle` (cancelled), collects `agent_message_chunk`s as the report, 10 min hard timeout, closes the session. Skills: sub-agents sync the union of all four professions' skills (serialised by a lock) so concurrent sub-agents don't prune each other's; the parent re-syncs its own list at its next turn. UI: `WorkflowView` in `tool-step.tsx` (rows from `args.tasks` merged with `subagents` events or the parsed output; `isWorkflowName` matches `Workflow` and `mcp__bytnode-ai__Workflow`). Token-free check: `scratchpad` MCP client against `lib/mcp/finance-server.ts` with the env above — `tools/list` must show Workflow at depth 0 only.

An assistant `Message` persists its `steps` (text / tool with status pending → running → done|failed|denied); `lib/agent/history.ts` (`stepsToMessages`) replays them in OpenRouter format, and `tool-calls.ts` reassembles streamed `tool_calls` fragments. Streaming text is smoothed in `use-chat.ts` (rAF reserve/reveal) and rendered per memoized block by `components/chat/markdown.tsx`.

**Settings.** `components/settings/settings-panel.tsx` is the settings panel (left nav: Général / Auth / Agents / Fournisseurs) opened from `chat-shell.tsx` with a `SettingsTarget` (`{ tab, agent? }`); every field saves immediately through `updateSettings`, only the agent form (reusing `StepAgent`) keeps a submit button and validation. `components/onboarding/wizard.tsx` is now first-launch only; `step-auth.tsx` exports `KeyField`/`OpenRouterKey`/`BytnodeKey`/`Subscriptions` so both share the same bricks. With no agent left, the panel is forced open on Agents in creation mode without a close button.

**Attachments / `+` menu.** `lib/agent/attachments.ts` (pure, tested: `safeFileName`, `attachmentNote`, `withDirectives`, `RESEARCH_DIRECTIVE`) + `lib/agent/capture.ts` (browser: `getDisplayMedia` one-frame capture, canvas downscale to JPEG 1600px) + `lib/agent/attach-client.ts` (upload + inline preview). Files land in `<workspace>/entrees/` via `POST /api/files/upload`; the model gets their **paths** in the message, not their content — images are additionally inlined (OpenRouter `image_url` in `history.ts`, ACP image content blocks in `connection.ts` gated on `promptCapabilities.image`). ⚠️ `use-chat.ts` substitutes `prompt` for the typed text in the last history entry whenever `prompt !== content` (compaction, attachments, research) — forgetting this makes the note invisible to the model. Screenshots are **browser-side on purpose**: PowerShell `CopyFromScreen` is blocked by Windows Defender AMSI as infostealer behaviour.

**Usage / context meter.** `lib/agent/usage.ts` (pure, tested) + `components/chat/usage-meter.tsx`, bottom-right of the thread: context/window, tok/s, cost, provider in the tooltip. Sources: OpenRouter's final-chunk `usage` (requested via `usage: { include: true }` in `completionBody`, parsed in `sse.ts` into `Delta.usage`/`Delta.provider`) and ACP `usage_update` (`translate.ts`). The loop emits `{type:"usage"}`; `use-chat.ts` merges it and measures the rate from revealed text.

**Loop safety.** `lib/agent/resilience.ts` (pure, tested): `isTransient` + `backoffDelay` retry a model turn up to `MAX_ATTEMPTS` **only while nothing has been emitted** (`acc.reset()` between attempts, `{type:"retry"}` event shown in the thread); `RepetitionGuard` refuses a 3rd identical tool call with a message telling the agent to change approach, and resets that counter on success. The loop stops with `finishReason: "max_turns"` if the model still emits tool calls on the tool-less last turn (it used to spin forever). Tool arguments that are not valid JSON come back as `ToolCall.argsError` ("Arguments illisibles…") rather than a misleading `{}`; well-formed ones are checked against the tool's JSON Schema **before** permission and execution (`lib/tools/validate.ts`, pure, tested — `type`/`required`/`enum`/`items`/`minimum`/`maximum`/`pattern`/`additionalProperties`, no dependency); an ill-formed call comes back to the model as a failed result ("Arguments invalides pour Read : `file_path` requis (string). Corrige l'appel.") without bothering the user. Covers the browser loop and Workflow sub-agents alike.

**Local-server security.** The app has no login: every `/api` route acts on the user's machine (writes files, spawns agents, opens system dialogs). `proxy.ts` (Next 16 proxy, matcher `/api/:path*`) refuses any request whose `Sec-Fetch-Site` is not `same-origin`/`none`, or whose `Origin` does not match `Host` (`lib/server/origin.ts`, pure, tested) — otherwise any web page could POST a `text/plain` body to `localhost:3777/api/acp/prompt` and run commands. Non-browser clients (curl, scripts) send neither header and pass. Never interpolate request data into a shell/PowerShell script: `app/api/system/pick-folder` passes the initial folder through `BYTNODE_AI_INITIAL_DIR` in the child's environment (a PowerShell `"…"` string evaluates `$(…)`). `/api/files` serves workspace files with `X-Content-Type-Options: nosniff` and a `Content-Security-Policy: sandbox` — an SVG written by an agent and opened in a tab must not run script in the app origin, where the keys live. Persistence: `Storage.set` returns `false` when `localStorage` is full; `ConversationsRepository.write` then retries without inline image `dataUrl`s (files stay on disk, served by `/api/files`) and finally throws `StorageFullError`, which `saveConversation` turns into an in-memory update plus the `useStorageFull()` notice in `chat-shell.tsx` — the thread must never roll back to the previous save.

**Resource bounds.** `lib/tools/exec/run.ts` caps what it keeps (`maxBytes`, default 200 kB) *and* the line buffer (`MAX_LINE` 1 MB: a stream without newlines is flushed in bounded pieces); `Read` refuses text files above `MAX_TEXT_BYTES` (50 MB) instead of loading them whole; `WebFetch` is capped at 5 MB / 100 k chars and refuses private/loopback addresses; `Grep` runs under a 60 s timeout; `ExchangeWatch`/`Monitor` are bounded to 10 min. `contextEstimate` (`usage.ts`) counts replayed tool arguments and outputs, not thoughts/plans — the pruning and auto-compaction thresholds depend on it. `lib/tools/exec/guard.ts` also flags `\…` drive-root and `\\server` UNC paths, `${env:X}` forms and location variables (ProgramFiles, SystemRoot, OneDrive…) — still a text guard, not a sandbox.

**Permissions.** `lib/tools/permissions.ts` (pure, tested): "Toujours" no longer flips the agent to `skip` — it stores a rule in `AgentConfig.allowRules` (`Write`, `Bash(git status *)`; sub-command kept only when it looks like one). `matchesRule` short-circuits the permission prompt; `isDangerous` (rm -rf, format, mkfs, force-push, curl|sh…) removes the "Toujours" button entirely and never matches a rule.

**Plan / reasoning.** `agent_thought_chunk` and `plan`/`plan_update` (ACP) and `delta.reasoning` (OpenRouter) become `thought`/`plan` steps, rendered by `message.tsx` and **never replayed** by `history.ts`.

**Compaction.** `lib/agent/compact.ts` (pure, tested): `isCompactCommand` detects `/compact [consignes]` in `use-chat.ts` `send()`. **The compaction is a hidden turn, like Claude Code's**: no user message is added, `buildCompactRequest(...)` is appended to the replayed history (OpenRouter) or sent as the ACP prompt, and the reply streams into a `Message` flagged `compacting: true` that `message.tsx` renders as a "Compactage du fil…" status line (never as a response; `stepsToMessages`/`transcriptOf` skip it, and a stale one left by a mid-turn reload is dropped at the next turn). When the turn ends cleanly the whole thread is replaced by one `Message` with `compaction: true` (`compactionMessage`), and for ACP agents the session is closed and `acpSessionId` cleared so the next turn starts fresh from the summary; aborted → the status line just disappears; failed → it disappears and `useChat().compactError` feeds a notice in `chat-shell.tsx` with « Réessayer ». `/compact` on an empty thread does nothing. `history.ts` replays a compaction message as a `user` message wrapped in `<resume_du_fil_precedent>`; `message.tsx` renders it as a folded boundary line (`CompactionView`, « voir le résumé »). There is no compact button: the composer proposes commands as soon as `/` is typed (`lib/agent/commands.ts`, pure, tested — `COMMANDS`, `matchCommands`; ↑↓ / Tab completes / Enter runs / Esc closes; a space after the name closes the list). `transcriptOf` is shared with the ACP history fallback. **Context is managed automatically for the OpenRouter engine** (`use-chat.ts`: `send` is a thin gate around an inner `turn` that can chain another turn, guarded by a `busy` ref rather than React state): (1) when `usageState(...).level !== "ok"` (≥ 70 % of `Model.contextLength`, passed in as `window`), the replayed history goes through `pruneToolOutputs(history, { keep: 6, head: 400 })` (`history.ts`, pure, tested — the 6 most recent tool results stay whole, older ones are cut to a head + "[… sortie élaguée …]" marker; the displayed thread is untouched); (2) a turn that ends cleanly at `level === "full"` (≥ 90 %) chains `/compact` with `compactedBy: "auto"`; (3) a provider "context length exceeded" error (`isContextOverflow`, pure, tested — 400/413 + wording) chains a hard-pruned compaction (`keep: 0, head: 200`) then replays the user's message (or a "Continue" prompt if the failed turn had already produced steps), once per turn (`recovered`). `Message.compactedBy` (`user` | `auto` | `overflow`) drives the label via `compactLabel`.

**System prompt** = `buildSystemPrompt(profile, agent)` (`lib/agent/prompt.ts`: user bio + profession `PROMPT.md` + agent context) + `buildToolsPrompt(...)` (`tools-prompt.ts`: workspace, scope, default shell, BytNode status, skill list). Both are assembled client-side from what `GET /api/tools` returns. `lib/agent/bytnode-guidance.ts` (pure, tested) is the cross-profession BytNode brief appended by both `tools-prompt.ts` and `lib/acp/prompt.ts` for main agents only (never sub-agents): recommend BytNode as the data source, name the plan that unlocks an out-of-plan request, say what data is missing, never pushy. The plan grid lives in `professions/_commun/skills/source-bytnode/SKILL.md`, a hand-kept mirror of `app_web/backend/src/db/seed/plans.catalog.ts` — update both.

**Tools** (`lib/tools/`). One file per tool implementing `Tool { name, description, parameters, execute(args, ctx) }`; `registry.ts` assembles `baseTools({platform})` and `allTools({platform, bytnodeKey, exchangeAccounts})` (base + dynamically discovered BytNode MCP tools + the exchange tools **only when the agent has at least one account**). `TodoWrite` (`todo.ts`, pure, tested) is the agent's task list: the full list every call, emitted as a `{type:"plan"}` event so it reuses the ACP plan block in `message.tsx` and is never replayed by `history.ts`. `names.ts` lists `GATED_TOOLS` (Bash, PowerShell, Monitor, Write, Edit, NotebookEdit, Workflow, Backtest, PlaceOrder, CancelOrder, ClosePosition, Transfer, SetLeverage) — the ones that wait for permission in `ask` mode — and `ALWAYS_ASK` (PlaceOrder, ClosePosition, Transfer), which ask **even in `skip` mode**, have no « Toujours » button and never match an allow rule (`permissions.ts` refuses them in `ruleFor`/`matchesRule`; `use-chat.ts` gates with `alwaysAsks(name) || (!skip && isGated(name))`). `ToolContext` carries `workspace`, `scope`, `projectRoot`, `signal`, `emit`, `depth`, `llm`, `callId`, `professionSkills`, `bytnodeKey`, `exchangeAccounts`.

**Finance tools** (`lib/tools/finance/`): `csv.ts` (pure table parsing / row discovery / column detection) and `svg.ts` (pure chart builder) are unit-tested; `data.ts` (SaveMarketData → CSV), `chart.ts` (SVG → PNG via `@resvg/resvg-js`, attachment carries `path` so the thread can show it through `/api/files`), `backtest.ts` (spawns `lib/tools/finance/py/backtest.py`, needs Python + pandas; gated), `memory.ts` (`.bytnode-ai/memory.jsonl`, rendered into the prompt each turn via `/api/memory`). The same four tools are exposed to ACP agents by `lib/mcp/finance-server.ts` (stdio MCP run with `tsx`, env `BYTNODE_AI_WORKSPACE` / `BYTNODE_AI_BYTNODE_KEY`), added to `session/new` in `lib/acp/sessions.ts`; image blocks in their results become `images` on the tool step (`translate.ts`). Tool images: `ToolAttachment.path` + `AgentEvent.tool_result.images` (`file:<rel>` or data URL).

**Scope / safety.** Each agent has a workspace (`~/.bytnode-ai/workspaces/<id>` by default, `lib/server/workspace.ts`; a legacy `workspaces/<id>` or `sandboxes/<id>` left in the project is moved there once — those dirs are git-ignored and hold real user data, never wipe them) and a `scope`: `workspace` (default) or `disk`. File tools go through `resolvePath(workspace, p, scope)` (`paths.ts`, throws `OutsideWorkspaceError`); shells go through `exec/guard.ts`, which refuses a command whose *text* references a path outside the workspace. Permission mode (`ask` | `skip`) is per agent and toggleable in the chat header. BytNode tools are read-only and never gated.

**Skills.** Four roots, in order (`lib/tools/skills/skill.ts`): `<workspace>/.agents/skills`, `<workspace>/skills`, `~/.bytnode-ai/skills` (the user's own, `userSkills()` — `skills/README.md` documents the format; nothing in the project is read), `~/.agents/skills`; profession skills are passed in first and win on name collision. ACP agents can't read those roots, so `lib/acp/skills-sync.ts` copies profession + project skills into `.agents/skills/` and `.claude/skills/` of the workspace (marked with `.bytnode-ai`; hand-written skills are never overwritten, removed ones are pruned, unchanged ones aren't rewritten) — called from `/api/acp/prompt`.

**Professions.** `professions/<id>/PROMPT.md` + `professions/<id>/skills/*/SKILL.md`, plus `professions/_commun/skills/` shared by all; ids and labels in `lib/professions/catalog.ts`, loading in `load.ts`. Adding a profession = a folder + an entry in `PROFESSIONS`. Skills are plain files with YAML front-matter (`name`, `description`); the `Skill` tool loads them on demand.

**Subscription agents (ACP)** (`lib/acp/`). Provider ids `acp:<id>` (`agents.ts`: claude, openai, gemini, copilot, grok, mistral) route a conversation to an external agent spawned by `launch.ts` with API-key env vars stripped. **Nothing is bundled**: `packages.ts` (`AGENT_SOURCES`, pure, tested) says where each agent comes from — an npm package (`@zed-industries/claude-agent-acp`, `@agentclientprotocol/codex-acp`, `@google/gemini-cli --acp`, `@github/copilot --acp`, `@xai-official/grok agent stdio`) or a binary from the ACP registry (Mistral Vibe) — and `resolveAcp` looks, in order, in `~/.bytnode-ai/agents/<id>/node_modules/<pkg>` (put there by « Installer »: `install.ts` writes a `package.json` with the pinned range + `overrides` and runs the `npm-cli.js` that ships with the running Node, `npmCli()`), then for gemini/copilot/grok on the PATH (`detect.ts` `findOnPath`, PATHEXT-aware; on Windows a `.cmd` shim is resolved back to the package script because Node refuses to spawn `.cmd` without a shell). `AcpAuthStatus.source` says which; `outdated` (installed version outside the table's range, `satisfiesCaret`) turns the button into « Mettre à jour ». Adding an agent = an entry in `ACP_AGENTS` + one in `AGENT_SOURCES`; auth/login/logout fall back to the generic protocol path (`auth.ts`: probe session, `authenticate` or terminal auth method) unless the agent has a dedicated CLI. `sessions.ts` keeps one ACP session per conversation (its key includes `toolsVersion()`, the newest mtime under `lib/tools` and `lib/mcp`, so editing any tool the MCP server embeds recreates the session and restarts the server) (server memory, 15 min idle TTL, `session/load` on restart via `Conversation.acpSessionId`), passes BytNode as an HTTP MCP server, and relays `session/update` → `WireEvent` (`translate.ts`, pure and tested) over NDJSON (`/api/acp/prompt`); permissions come back through `/api/acp/permission`. `use-chat.ts` picks the engine from `acpAgentOf(agent.providerId)`. Models come from the agent's session config options (`models.ts`, cached) and are merged into the catalog store with `acp:` ids. Login state: `auth.ts` — a dedicated CLI for claude/openai/gemini, otherwise a probe session whose result is cached 90 s; the first read returns `checking: true` and fills in the background (the client store polls while any agent is `checking`), so the page never waits on a subprocess; the probe's `session/new` is bounded by `PROBE_TIMEOUT` (45 s) so a mute agent ends as "ne répond pas" instead of `checking` forever. `connection.ts` drops stray JSON-RPC responses with string ids before they reach the SDK — Grok Build pushes `skills-reload`/`workflows-reload` messages that would otherwise log "Got response to unknown request" on every session. Claude needs `.claude/settings.local.json` with a known `permissions.defaultMode` in the workspace (`prepare.ts`) — the adapter rejects unknown modes such as `auto` from the user's own settings. **The Claude model list comes from the Claude Agent SDK the adapter embeds**, not from the adapter itself: `@zed-industries/claude-agent-acp` 0.23.1 (March 2026, unmaintained since) pins `@anthropic-ai/claude-agent-sdk` 0.2.83, whose list stops at Sonnet/Haiku/Opus — the `overrides` in `AGENT_SOURCES.claude` (written into the install `package.json`) forces `^0.3.270` (Fable appears, efforts gain `xhigh`, session opening drops from 14 s to 5 s). The SDK 0.3 ships Claude Code as a native binary in a per-platform package (`@anthropic-ai/claude-agent-sdk-win32-x64/claude.exe`…, resolved by `claudeCli()` in `launch.ts`; no more `cli.js`). On Windows `openTerminal` writes the `cmd /c start … cmd /k "…"` line by hand with `windowsVerbatimArguments` — letting Node quote the arguments produced `\"` that `start` read as a program named `Claude\"`. Bump that override in `packages.ts`, not the adapter, when new models ship (users see « Mettre à jour »); verify with a scratch `discoverOffer("claude", true)` (no tokens) plus one haiku/low turn. The adapter also ignores the model we pass at `session/new` (`_meta.claudeCode.options.model`): it starts on the user's `~/.claude/settings.json` model and `applyConfig` (`sessions.ts`) corrects it through `session/set_config_option` before the first prompt — keep that call.

**Exchange trading** (`lib/tools/exchange/`, `ccxt` v4 — server-only, in `serverExternalPackages`). Accounts (`ExchangeAccount { id, exchange (ccxt id), label, apiKey, secret, password, testnet }`) live in `Settings.keys.exchanges` (settings **v3**, migrated in `repositories.ts`); each agent picks the ones it may drive in `AgentConfig.exchangeAccountIds`. The browser sends the agent's allowed accounts (`allowedAccounts`, `accounts.ts`) as the `x-exchange-accounts` header (URI-encoded JSON — a label may hold non-Latin-1 characters; `encodeAccountsHeader`/`parseAccountsHeader`) on `/api/tools` and `/api/tools/execute` (`lib/tools/client.ts`), as `exchangeAccounts` in the `/api/acp/prompt` body, and `sessions.ts` forwards them to `finance-server.ts` through `BYTNODE_AI_EXCHANGE_ACCOUNTS` — never written to disk, never logged. `client.ts` (`clientFor(account, market)`) caches one ccxt instance per sha256(account × market) with `loadMarkets()` done once, `defaultType: swap` for futures, `setSandboxMode` for testnet; `common.ts` (`resolve`, `symbolOn`, `attempt`, `hedgeModeError`) is the shared trunk of the ten tools: `ExchangeBalance`, `ExchangePositions`, `ExchangeOrders`, `ExchangeTicker`, `ExchangeWatch` (bounded polling like `Monitor`, `tool_line` events, `until` grammar in `watch-until.ts`) — read-only — and `PlaceOrder` (`amount` **or** `quoteAmount`, precision/minimum checks, ccxt `triggerPrice`/`takeProfitPrice` params), `CancelOrder`, `ClosePosition` (market reduceOnly), `Transfer` (spot ↔ swap of the same account, **no external withdrawal exists**), `SetLeverage`. **Workflow sub-agents never receive the five action tools** (`allowedForSubagent`, `names.ts`) — they have nobody to ask. `client.ts` only instantiates ids listed in `ccxt.exchanges` (never an arbitrary property such as `constructor`). Futures are one-way only (`fetchPositionMode` → refuse hedge mode); symbols are normalised by `symbols.ts` (`BTC/USDT` + futures → `BTC/USDT:USDT`); errors by `errors.ts` (ccxt `error.name` → French, `withRetry` once on transient; a `recv_window`/timestamp refusal is named as a clock skew with the measured gap). **Clock:** Binance and Bybit require `timestamp < server_time + 1 s` — a PC clock one second ahead fails everything and no `recvWindow` helps — so `client.ts` calls `loadTimeDifference()` **before** `loadMarkets()` (Bybit hits a private endpoint during `loadMarkets`, before ccxt's own measurement) and again every 10 min on the cached client (`syncClock`), with `adjustForTimeDifference: true` + `recvWindow: 10_000`. **Per-exchange limits live in `catalog.ts`** (`ExchangeInfo.futures: full|read|none`, `futuresId` (KuCoin futures = the `kucoinfutures` class, same keys), `transfer`, `note`), measured on ccxt `has`/`urls.test` and the exchanges' docs: Coinbase/Kraken are spot-only here (`resolve` refuses `market: futures`), MEXC futures are read-only (MEXC closed order placement by API in 2022 — `futuresActionError`), Bybit/OKX unified accounts have nothing to transfer, HTX linear-swap transfers aren't in ccxt, Gate/HTX have no `setMarginMode`, OKX/Coinbase have no `cancelAllOrders` (CancelOrder loops over open orders). `hedgeModeError` reads Bybit's `positionIdx` and Bitget's account `posMode` since neither has `fetchPositionMode`; trigger orders carry `triggerDirection` (required by Bybit/KuCoin futures, refused by Bybit spot); the order book is asked with 20 or 100 levels (KuCoin accepts nothing else) then sliced; a Coinbase CDP secret goes through `pemSecret` (literal `\n`, flattened PEM). `ExchangeInfo.funding` names the wallet where deposits land when it is not the trading account (Bybit/OKX `funding`, KuCoin `main`, Binance `funding`): `ExchangeBalance` and `/api/exchange/check` read it too (`fundingRows`) — "connecté, aucun solde" with 40 USDC sitting in Bybit's Funding wallet was the symptom — and `Transfer` accepts `funding` as a wallet (`tradingWallet: "unified"` on Bybit). `exchangePromptSection` lists these limits to the agent. Live check without keys: `scratchpad/live-tools.mts` runs `ExchangeTicker` on all 10 × spot/futures × live/testnet. Pure modules are tested; tool tests mock `./client` with `vi.mock` and a fake exchange (`test-fixture.ts`) — **never call a real exchange in tests**; end-to-end checks go through a testnet account (Binance / Bybit). UI: `components/onboarding/exchange-accounts.tsx` (+ `POST /api/exchange/check`), account checkboxes in `step-agent.tsx`, a RÉEL/TESTNET badge in the chat header and in the permission prompt (`ExchangeBadge` in `tool-step.tsx`; an ambiguous account shows RÉEL). ACP: the same tools are served by `finance-server.ts`; `sessions.ts` still asks the user for an `ALWAYS_ASK` tool title even when the agent is in `skip` (`isAlwaysAskTitle`) and never answers `allow_always` for it, but an external agent whose own mode bypasses permissions may never ask — documented limitation. Prompt section: `exchangePromptSection` (`prompt.ts`), shared by `tools-prompt.ts` and `lib/acp/prompt.ts`; skills `trading-execution` and `trade-review` in `professions/_commun/skills/`.

**BytNode MCP** (`lib/mcp/bytnode.ts`): StreamableHTTP client, `X-API-KEY` header, one cached session per key, `checkBytnodeKey` behind `GET /api/bytnode/key`.

**State.** All persistence is `localStorage` via `useSyncExternalStore` stores in `lib/state/` (`agentchat:settings` v2 with `agents[]` + `activeAgentId`, `agentchat:conversations`, `agentchat:ui` for sidebar width/collapse). `lib/storage/repositories.ts` migrates v1 data lazily under `LEGACY_AGENT_ID = "agent-1"`; new agents get `id: ""` from `blankAgent()` and are stamped in `app/page.tsx` at creation.

**Provider routing.** Every OpenRouter call carries `provider: PROVIDER_ROUTING` (`lib/server/provider-routing.ts`, pure + tested): `sort: "latency"` and `ignore: ["parasail"]` by default, overridable via `OPENROUTER_PROVIDER_SORT` / `OPENROUTER_IGNORE_PROVIDERS` / `OPENROUTER_PROVIDER_ORDER` / `OPENROUTER_ALLOW_FALLBACKS`. Without it OpenRouter load-balances and the same turn measured 3 s vs 34 s vs 98 s. Applied in `completionBody` (chat relay + Workflow sub-agents) and in `lib/tools/web/search.ts`.

**Model catalog** (`lib/catalog/catalog.ts`): providers are derived from the id prefix; `:variant` ids and `~alias` ids are excluded from "latest" but remain searchable. Reasoning effort options come from OpenRouter's `reasoning.supported_efforts`; `effortOptions()` appends `none` unless reasoning is mandatory — always validate an effort through it. ACP models are merged by `lib/catalog/use-catalog.ts` (`loadAcpModels`, tested): on a cold server the first `/api/acp/models` takes 15–55 s (every logged-in agent is spawned to publish its models) while the protocol-probed agents (grok, copilot, mistral) flip from `checking` to `loggedIn` in 2–5 s — a reload requested during an in-flight load is **queued and replayed**, never dropped, and `Catalog.acpLoading` tells the picker to say "lecture en cours" rather than "aucun modèle".

## Testing conventions

Unit tests sit next to their module in `lib/` (Vitest, node env, no DOM). The agent loop, SSE parsing, path resolution, shell guard, edit/notebook logic, catalog, storage migration and profession loading are all covered — extend those files rather than adding UI tests. Real-model end-to-end checks are done with throwaway scripts in the scratchpad against a mock OpenRouter (`OPENROUTER_BASE_URL`), never committed.

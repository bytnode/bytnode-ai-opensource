@AGENTS.md

## What this is

BytNode-AI: a local Next.js 16 (App Router, Turbopack) + React 19 + TypeScript-strict app. Multi-agent finance chat on OpenRouter; each agent has a *profession* (prompt + skills loaded from `professions/`), a tool set (`lib/tools/`), and BytNode market data via a remote MCP server. UI text, comments and commit-style prose are in French; keep it that way. CSS is hand-written (no Tailwind) using the BytNode tokens (`--ink`, `--paper`, `--voile`) and fonts (Geist / Inter / IBM Plex Mono) — see `README.md` for the full layout.

## Commands

```bash
npm run dev          # http://localhost:3777 — the user usually already runs this; do NOT start a second one
npm run typecheck    # tsc --noEmit
npm run lint         # eslint (next core-web-vitals + typescript, React Compiler rules)
npm test             # vitest run — only lib/**/*.test.ts, node environment
npm run test:watch   # vitest en mode watch
npx vitest run lib/tools/paths.test.ts        # single file
npx vitest run -t "refuse un chemin"          # single test by name
npm run build
```

Before reporting a change as done: `typecheck`, `lint`, `test` must all be clean.

Environment (server-side, optional): `OPENROUTER_BASE_URL` (relay / fake OpenRouter), `OPENROUTER_SEARCH_MODEL`, `BYTNODE_MCP_URL`. The OpenRouter key is **not** read from env by the app — it lives in the browser's `localStorage` and travels per request in the `x-openrouter-key` header (`lib/server/openrouter.ts`); the BytNode key uses `x-bytnode-key`. `.env.local` holds a real key used only by ad-hoc test scripts: never print it. Real-model probes of the ACP path cost the user's subscription quota — keep them short (`haiku`, `effort: low`).

## Constraints that are not obvious from the code

- Next 16 refuses two `next dev` in the same directory, and port 3777 is the user's. Don't leave background servers running; kill anything you started.
- Bash tool heredocs mangle backslashes on this machine — write files with the Write tool (or a python patch script in the scratchpad) rather than `cat <<EOF`.
- ESLint runs the React Compiler rules: no `Date.now()`/random ids in render (stamp ids at creation), no `setState` inside effects (key the component instead), stable `useCallback` deps.
- Packages with native binaries or runtime `require` (`@vscode/ripgrep`, `pdf-parse`, `turndown`, `fast-glob`, `@agentclientprotocol/sdk`, `@resvg/resvg-js`) must stay in `serverExternalPackages` in `next.config.ts`. `pdf-parse` v2 is class-based (`new PDFParse({data}).getText()`).
- `bytnode_api/.mcp.json` (if present) contains a live key — never reuse it.

## Architecture (what you need across several files)

**Isomorphic agent loop.** `lib/agent/loop.ts` (`runAgentLoop(messages, deps)`) is the model → tools → model cycle, max 40 turns. It is dependency-injected and runs in two places:
- *Browser*, for the main agent (`components/chat/use-chat.ts`): model via `POST /api/chat` (SSE relay, `lib/llm/client.ts` + `sse.ts`), tools via `POST /api/tools/execute` (NDJSON stream of lines / sub-agent events / result), permissions resolved by UI promises (`answer(callId, allow, always)`).
- *Server*, for Workflow sub-agents (`lib/tools/agents/workflow.ts`), everything in-process.

An assistant `Message` persists its `steps` (text / tool with status pending → running → done|failed|denied); `lib/agent/history.ts` (`stepsToMessages`) replays them in OpenRouter format, and `tool-calls.ts` reassembles streamed `tool_calls` fragments. Streaming text is smoothed in `use-chat.ts` (rAF reserve/reveal) and rendered per memoized block by `components/chat/markdown.tsx`.

**Attachments / `+` menu.** `lib/agent/attachments.ts` (pure, tested: `safeFileName`, `attachmentNote`, `withDirectives`, `RESEARCH_DIRECTIVE`) + `lib/agent/capture.ts` (browser: `getDisplayMedia` one-frame capture, canvas downscale to JPEG 1600px) + `lib/agent/attach-client.ts` (upload + inline preview). Files land in `<workspace>/entrees/` via `POST /api/files/upload`; the model gets their **paths** in the message, not their content — images are additionally inlined (OpenRouter `image_url` in `history.ts`, ACP image content blocks in `connection.ts` gated on `promptCapabilities.image`). ⚠️ `use-chat.ts` substitutes `prompt` for the typed text in the last history entry whenever `prompt !== content` (compaction, attachments, research) — forgetting this makes the note invisible to the model. Screenshots are **browser-side on purpose**: PowerShell `CopyFromScreen` is blocked by Windows Defender AMSI as infostealer behaviour.

**Usage / context meter.** `lib/agent/usage.ts` (pure, tested) + `components/chat/usage-meter.tsx`, bottom-right of the thread: context/window, tok/s, cost, provider in the tooltip. Sources: OpenRouter's final-chunk `usage` (requested via `usage: { include: true }` in `completionBody`, parsed in `sse.ts` into `Delta.usage`/`Delta.provider`) and ACP `usage_update` (`translate.ts`). The loop emits `{type:"usage"}`; `use-chat.ts` merges it and measures the rate from revealed text.

**Loop safety.** `lib/agent/resilience.ts` (pure, tested): `isTransient` + `backoffDelay` retry a model turn up to `MAX_ATTEMPTS` **only while nothing has been emitted** (`acc.reset()` between attempts, `{type:"retry"}` event shown in the thread); `RepetitionGuard` refuses a 3rd identical tool call with a message telling the agent to change approach, and resets that counter on success. The loop stops with `finishReason: "max_turns"` if the model still emits tool calls on the tool-less last turn (it used to spin forever). Tool arguments that are not valid JSON come back as `ToolCall.argsError` ("Arguments illisibles…") rather than a misleading `{}`; well-formed ones are checked against the tool's JSON Schema **before** permission and execution (`lib/tools/validate.ts`, pure, tested — `type`/`required`/`enum`/`items`/`minimum`/`maximum`/`pattern`/`additionalProperties`, no dependency); an ill-formed call comes back to the model as a failed result ("Arguments invalides pour Read : `file_path` requis (string). Corrige l'appel.") without bothering the user. Covers the browser loop and Workflow sub-agents alike.

**Local-server security.** The app has no login: every `/api` route acts on the user's machine (writes files, spawns agents, opens system dialogs). `proxy.ts` (Next 16 proxy, matcher `/api/:path*`) refuses any request whose `Sec-Fetch-Site` is not `same-origin`/`none`, or whose `Origin` does not match `Host` (`lib/server/origin.ts`, pure, tested) — otherwise any web page could POST a `text/plain` body to `localhost:3777/api/acp/prompt` and run commands. Non-browser clients (curl, scripts) send neither header and pass. Never interpolate request data into a shell/PowerShell script: `app/api/system/pick-folder` passes the initial folder through `BYTNODE_AI_INITIAL_DIR` in the child's environment (a PowerShell `"…"` string evaluates `$(…)`). `/api/files` serves workspace files with `X-Content-Type-Options: nosniff` and a `Content-Security-Policy: sandbox` — an SVG written by an agent and opened in a tab must not run script in the app origin, where the keys live. Persistence: `Storage.set` returns `false` when `localStorage` is full; `ConversationsRepository.write` then retries without inline image `dataUrl`s (files stay on disk, served by `/api/files`) and finally throws `StorageFullError`, which `saveConversation` turns into an in-memory update plus the `useStorageFull()` notice in `chat-shell.tsx` — the thread must never roll back to the previous save.

**Resource bounds.** `lib/tools/exec/run.ts` caps what it keeps (`maxBytes`, default 200 kB) *and* the line buffer (`MAX_LINE` 1 MB: a stream without newlines is flushed in bounded pieces); `Read` refuses text files above `MAX_TEXT_BYTES` (50 MB) instead of loading them whole; `WebFetch` is capped at 5 MB / 100 k chars and refuses private/loopback addresses; `Grep` runs under a 60 s timeout; `ExchangeWatch`/`Monitor` are bounded to 10 min. `contextEstimate` (`usage.ts`) counts replayed tool arguments and outputs, not thoughts/plans — the pruning and auto-compaction thresholds depend on it. `lib/tools/exec/guard.ts` also flags `\…` drive-root and `\\server` UNC paths, `${env:X}` forms and location variables (ProgramFiles, SystemRoot, OneDrive…) — still a text guard, not a sandbox.

**Permissions.** `lib/tools/permissions.ts` (pure, tested): "Toujours" no longer flips the agent to `skip` — it stores a rule in `AgentConfig.allowRules` (`Write`, `Bash(git status *)`; sub-command kept only when it looks like one). `matchesRule` short-circuits the permission prompt; `isDangerous` (rm -rf, format, mkfs, force-push, curl|sh…) removes the "Toujours" button entirely and never matches a rule.

**Plan / reasoning.** `agent_thought_chunk` and `plan`/`plan_update` (ACP) and `delta.reasoning` (OpenRouter) become `thought`/`plan` steps, rendered by `message.tsx` and **never replayed** by `history.ts`.

**Compaction.** `lib/agent/compact.ts` (pure, tested): `isCompactCommand` detects `/compact [consignes]` in `use-chat.ts` `send()`, which substitutes `buildCompactRequest(...)` for the typed text (the visible user message keeps `/compact`). When the turn ends cleanly the whole thread is replaced by one `Message` with `compaction: true` (`compactionMessage`), and for ACP agents the session is closed and `acpSessionId` cleared so the next turn starts fresh from the summary. `history.ts` replays a compaction message as a `user` message wrapped in `<resume_du_fil_precedent>`; `message.tsx` renders it as a quoted block. `transcriptOf` is shared with the ACP history fallback. **Context is managed automatically for the OpenRouter engine** (`use-chat.ts`: `send` is a thin gate around an inner `turn` that can chain another turn, guarded by a `busy` ref rather than React state): (1) when `usageState(...).level !== "ok"` (≥ 70 % of `Model.contextLength`, passed in as `window`), the replayed history goes through `pruneToolOutputs(history, { keep: 6, head: 400 })` (`history.ts`, pure, tested — the 6 most recent tool results stay whole, older ones are cut to a head + "[… sortie élaguée …]" marker; the displayed thread is untouched); (2) a turn that ends cleanly at `level === "full"` (≥ 90 %) chains `/compact` with `compactedBy: "auto"`; (3) a provider "context length exceeded" error (`isContextOverflow`, pure, tested — 400/413 + wording) chains a hard-pruned compaction (`keep: 0, head: 200`) then replays the user's message (or a "Continue" prompt if the failed turn had already produced steps), once per turn (`recovered`). `Message.compactedBy` (`user` | `auto` | `overflow`) drives the label via `compactLabel`.

**System prompt** = `buildSystemPrompt(profile, agent)` (`lib/agent/prompt.ts`: user bio + profession `PROMPT.md` + agent context) + `buildToolsPrompt(...)` (`tools-prompt.ts`: workspace, scope, default shell, BytNode status, skill list). Both are assembled client-side from what `GET /api/tools` returns.

**Tools** (`lib/tools/`). One file per tool implementing `Tool { name, description, parameters, execute(args, ctx) }`; `registry.ts` assembles `baseTools({platform})` and `allTools({platform, bytnodeKey, exchangeAccounts})` (base + dynamically discovered BytNode MCP tools + the exchange tools **only when the agent has at least one account**). `TodoWrite` (`todo.ts`, pure, tested) is the agent's task list: the full list every call, emitted as a `{type:"plan"}` event so it reuses the ACP plan block in `message.tsx` and is never replayed by `history.ts`. `names.ts` lists `GATED_TOOLS` (Bash, PowerShell, Monitor, Write, Edit, NotebookEdit, Workflow, Backtest, PlaceOrder, CancelOrder, ClosePosition, Transfer, SetLeverage) — the ones that wait for permission in `ask` mode — and `ALWAYS_ASK` (PlaceOrder, ClosePosition, Transfer), which ask **even in `skip` mode**, have no « Toujours » button and never match an allow rule (`permissions.ts` refuses them in `ruleFor`/`matchesRule`; `use-chat.ts` gates with `alwaysAsks(name) || (!skip && isGated(name))`). `ToolContext` carries `workspace`, `scope`, `projectRoot`, `signal`, `emit`, `depth`, `llm`, `callId`, `professionSkills`, `bytnodeKey`, `exchangeAccounts`.

**Finance tools** (`lib/tools/finance/`): `csv.ts` (pure table parsing / row discovery / column detection) and `svg.ts` (pure chart builder) are unit-tested; `data.ts` (SaveMarketData → CSV), `chart.ts` (SVG → PNG via `@resvg/resvg-js`, attachment carries `path` so the thread can show it through `/api/files`), `backtest.ts` (spawns `py/backtest.py`, needs Python + pandas; gated), `memory.ts` (`.bytnode-ai/memory.jsonl`, rendered into the prompt each turn via `/api/memory`). The same four tools are exposed to ACP agents by `lib/mcp/finance-server.ts` (stdio MCP run with `tsx`, env `BYTNODE_AI_WORKSPACE` / `BYTNODE_AI_BYTNODE_KEY`), added to `session/new` in `lib/acp/sessions.ts`; image blocks in their results become `images` on the tool step (`translate.ts`). Tool images: `ToolAttachment.path` + `AgentEvent.tool_result.images` (`file:<rel>` or data URL).

**Scope / safety.** Each agent has a workspace (`workspaces/<id>` by default, `lib/server/workspace.ts`; a legacy `sandboxes/<id>` is reused if it still exists — both dirs are git-ignored and hold real user data, never wipe them) and a `scope`: `workspace` (default) or `disk`. File tools go through `resolvePath(workspace, p, scope)` (`paths.ts`, throws `OutsideWorkspaceError`); shells go through `exec/guard.ts`, which refuses a command whose *text* references a path outside the workspace. Permission mode (`ask` | `skip`) is per agent and toggleable in the chat header. BytNode tools are read-only and never gated.

**Skills.** Four roots, in order (`lib/tools/skills/skill.ts`): `<workspace>/.agents/skills`, `<workspace>/skills`, `<projectRoot>/skills` (the user's own — `skills/README.md` documents the format), `~/.agents/skills`; profession skills are passed in first and win on name collision. ACP agents can't read those roots, so `lib/acp/skills-sync.ts` copies profession + project skills into `.agents/skills/` and `.claude/skills/` of the workspace (marked with `.bytnode-ai`; hand-written skills are never overwritten, removed ones are pruned, unchanged ones aren't rewritten) — called from `/api/acp/prompt`.

**Professions.** `professions/<id>/PROMPT.md` + `professions/<id>/skills/*/SKILL.md`, plus `professions/_commun/skills/` shared by all; ids and labels in `lib/professions/catalog.ts`, loading in `load.ts`. Adding a profession = a folder + an entry in `PROFESSIONS`. Skills are plain files with YAML front-matter (`name`, `description`); the `Skill` tool loads them on demand.

**Subscription agents (ACP)** (`lib/acp/`). Provider ids `acp:<id>` (`agents.ts`: claude, openai, gemini, copilot, grok, mistral) route a conversation to an external agent spawned by `launch.ts` with API-key env vars stripped — npm-distributed ones (`@zed-industries/claude-agent-acp`, `@agentclientprotocol/codex-acp`, `@google/gemini-cli --acp`, `@github/copilot --acp`, `@xai-official/grok agent stdio`) or binaries downloaded from the ACP registry into `~/.bytnode-ai/agents/<id>/` by `install.ts` (Mistral Vibe). Adding an agent = an entry in `ACP_AGENTS` + a launch spec (+ a registry source if downloaded); auth/login/logout fall back to the generic protocol path (`auth.ts`: probe session, `authenticate` or terminal auth method) unless the agent has a dedicated CLI. `sessions.ts` keeps one ACP session per conversation (its key includes `toolsVersion()`, the newest mtime under `lib/tools` and `lib/mcp`, so editing any tool the MCP server embeds recreates the session and restarts the server) (server memory, 15 min idle TTL, `session/load` on restart via `Conversation.acpSessionId`), passes BytNode as an HTTP MCP server, and relays `session/update` → `WireEvent` (`translate.ts`, pure and tested) over NDJSON (`/api/acp/prompt`); permissions come back through `/api/acp/permission`. `use-chat.ts` picks the engine from `acpAgentOf(agent.providerId)`. Models come from the agent's session config options (`models.ts`, cached) and are merged into the catalog store with `acp:` ids. Login state: `auth.ts` — a dedicated CLI for claude/openai/gemini, otherwise a probe session whose result is cached 90 s; the first read returns `checking: true` and fills in the background (the client store polls while any agent is `checking`), so the page never waits on a subprocess; the probe's `session/new` is bounded by `PROBE_TIMEOUT` (45 s) so a mute agent ends as "ne répond pas" instead of `checking` forever. `connection.ts` drops stray JSON-RPC responses with string ids before they reach the SDK — Grok Build pushes `skills-reload`/`workflows-reload` messages that would otherwise log "Got response to unknown request" on every session. Claude needs `.claude/settings.local.json` with a known `permissions.defaultMode` in the workspace (`prepare.ts`) — the adapter rejects unknown modes such as `auto` from the user's own settings.

**Exchange trading** (`lib/tools/exchange/`, `ccxt` v4 — server-only, in `serverExternalPackages`). Accounts (`ExchangeAccount { id, exchange (ccxt id), label, apiKey, secret, password, testnet }`) live in `Settings.keys.exchanges` (settings **v3**, migrated in `repositories.ts`); each agent picks the ones it may drive in `AgentConfig.exchangeAccountIds`. The browser sends the agent's allowed accounts (`allowedAccounts`, `accounts.ts`) as the `x-exchange-accounts` header (URI-encoded JSON — a label may hold non-Latin-1 characters; `encodeAccountsHeader`/`parseAccountsHeader`) on `/api/tools` and `/api/tools/execute` (`lib/tools/client.ts`), as `exchangeAccounts` in the `/api/acp/prompt` body, and `sessions.ts` forwards them to `finance-server.ts` through `BYTNODE_AI_EXCHANGE_ACCOUNTS` — never written to disk, never logged. `client.ts` (`clientFor(account, market)`) caches one ccxt instance per sha256(account × market) with `loadMarkets()` done once, `defaultType: swap` for futures, `setSandboxMode` for testnet; `common.ts` (`resolve`, `symbolOn`, `attempt`, `hedgeModeError`) is the shared trunk of the ten tools: `ExchangeBalance`, `ExchangePositions`, `ExchangeOrders`, `ExchangeTicker`, `ExchangeWatch` (bounded polling like `Monitor`, `tool_line` events, `until` grammar in `watch-until.ts`) — read-only — and `PlaceOrder` (`amount` **or** `quoteAmount`, precision/minimum checks, ccxt `triggerPrice`/`takeProfitPrice` params), `CancelOrder`, `ClosePosition` (market reduceOnly), `Transfer` (spot ↔ swap of the same account, **no external withdrawal exists**), `SetLeverage`. **Workflow sub-agents never receive the five action tools** (`allowedForSubagent`, `names.ts`) — they have nobody to ask. `client.ts` only instantiates ids listed in `ccxt.exchanges` (never an arbitrary property such as `constructor`). Futures are one-way only (`fetchPositionMode` → refuse hedge mode); symbols are normalised by `symbols.ts` (`BTC/USDT` + futures → `BTC/USDT:USDT`); errors by `errors.ts` (ccxt `error.name` → French, `withRetry` once on transient). Pure modules are tested; tool tests mock `./client` with `vi.mock` and a fake exchange (`test-fixture.ts`) — **never call a real exchange in tests**; end-to-end checks go through a testnet account (Binance / Bybit). UI: `components/onboarding/exchange-accounts.tsx` (+ `POST /api/exchange/check`), account checkboxes in `step-agent.tsx`, a RÉEL/TESTNET badge in the chat header and in the permission prompt (`ExchangeBadge` in `tool-step.tsx`; an ambiguous account shows RÉEL). ACP: the same tools are served by `finance-server.ts`; `sessions.ts` still asks the user for an `ALWAYS_ASK` tool title even when the agent is in `skip` (`isAlwaysAskTitle`) and never answers `allow_always` for it, but an external agent whose own mode bypasses permissions may never ask — documented limitation. Prompt section: `exchangePromptSection` (`prompt.ts`), shared by `tools-prompt.ts` and `lib/acp/prompt.ts`; skills `trading-execution` and `trade-review` in `professions/_commun/skills/`.

**BytNode MCP** (`lib/mcp/bytnode.ts`): StreamableHTTP client, `X-API-KEY` header, one cached session per key, `checkBytnodeKey` behind `GET /api/bytnode/key`.

**State.** All persistence is `localStorage` via `useSyncExternalStore` stores in `lib/state/` (`agentchat:settings` v2 with `agents[]` + `activeAgentId`, `agentchat:conversations`, `agentchat:ui` for sidebar width/collapse). `lib/storage/repositories.ts` migrates v1 data lazily under `LEGACY_AGENT_ID = "agent-1"`; new agents get `id: ""` from `blankAgent()` and are stamped in `app/page.tsx` at creation.

**Provider routing.** Every OpenRouter call carries `provider: PROVIDER_ROUTING` (`lib/server/provider-routing.ts`, pure + tested): `sort: "latency"` and `ignore: ["parasail"]` by default, overridable via `OPENROUTER_PROVIDER_SORT` / `OPENROUTER_IGNORE_PROVIDERS` / `OPENROUTER_PROVIDER_ORDER` / `OPENROUTER_ALLOW_FALLBACKS`. Without it OpenRouter load-balances and the same turn measured 3 s vs 34 s vs 98 s. Applied in `completionBody` (chat relay + Workflow sub-agents) and in `lib/tools/web/search.ts`.

**Model catalog** (`lib/catalog/catalog.ts`): providers are derived from the id prefix; `:variant` ids and `~alias` ids are excluded from "latest" but remain searchable. Reasoning effort options come from OpenRouter's `reasoning.supported_efforts`; `effortOptions()` appends `none` unless reasoning is mandatory — always validate an effort through it. ACP models are merged by `lib/catalog/use-catalog.ts` (`loadAcpModels`, tested): on a cold server the first `/api/acp/models` takes 15–55 s (every logged-in agent is spawned to publish its models) while the protocol-probed agents (grok, copilot, mistral) flip from `checking` to `loggedIn` in 2–5 s — a reload requested during an in-flight load is **queued and replayed**, never dropped, and `Catalog.acpLoading` tells the picker to say "lecture en cours" rather than "aucun modèle".

## Testing conventions

Unit tests sit next to their module in `lib/` (Vitest, node env, no DOM). The agent loop, SSE parsing, path resolution, shell guard, edit/notebook logic, catalog, storage migration and profession loading are all covered — extend those files rather than adding UI tests. Real-model end-to-end checks are done with throwaway scripts in the scratchpad against a mock OpenRouter (`OPENROUTER_BASE_URL`), never committed.
